# 引き継ぎサマリ — がんばっタネ / EngineerFlowers

> AI/将来セッション向けの現在地。最初にこれを読めば全体像と「次にやること」が分かる。

## このプロジェクトは何か

家庭を持つエンジニア向けの iOS アプリ。子育てやプライベートで焦る人が、開くと自然と落ち着く場所を作る。
GitHubの草をオマージュしたカレンダー状の庭に、何もしなくても草が生え、今日あったことはタネをはじいて飛ばすと**ネオンの紫陽花**になる。草むらには開発者の子どもを写したユジュとトゥーリがいる。
個人開発・SwiftUI・自分専用（Apple Intelligence前提）から始める。判断基準は「開発者本人が欲しいと思えるか」。

## ドキュメントの読む順

1. `プロダクト概要.md` … 3本の柱・芯・ペルソナ・機能カタログ
2. `タネと色.md` … 1日のマスの決まり方、タネの流れ、配色
3. `ビジュアルディレクション.md` … 見え方・キャラ・タネを飛ばす・咲くアニメ
4. `画面フロー.md` … 使われ方・連携
5. `確定事項.md` / `未決定事項.md` … 確定／未決定の索引

## 現在地（2026-10）

- **2026-10 にコンセプトを再設計した。** 以前の芯は「頑張りを採点して花にする」（量で花の大きさが決まる）だったが、落ち着くアプリと衝突するため廃止し、「採点ではなく肯定」に転換した。廃止した決定は `確定事項.md` の末尾に一覧がある
- コンセプトの骨格は確定。docsは新コンセプトに統合改訂済み
- 旧コンセプトから持ち越した機能（課金、言語マスコット、季節、水やり、コミュニティ等）は**未検討のまま**残っている。勝手に前提にしない
- 実装は未着手。HTMLの検討用プロトタイプが `previews/` にある

## 設計で守る軸（ブレないための要点）

- **落ち着くことが最優先**：追い立てない。催促・リマインダー・反応ブースト・連続記録の圧を置かない
- **量を測らない**：どの日の花も同じ大きさ。違いは色（何があった日か）だけ。量を表す仕組みを別の形で持ち込まない（トゥーリの成長が日数で進むのもこのため）
- **空白の日は存在しない**：草は必ず生える。ただし本人が何も言っていない日に花は咲かせない
- **タネは自分ではじいて飛ばす**：連携は拾ってくる係。蒔き残しはトゥーリが蒔く
- **話しかけるのはユジュだけ**：空いた日はまとめて1回、開いたときにだけ聞く。答えは肯定で返す
- **願いは1年単位で、年の画面に属する**：目標や宿題ではなく願いごと。Xへの公開は任意で、引き寄せの感覚
- **特別なのは願いが叶った日だけ**：特別な花が咲き、年の草むらがコレクションになる
- **花はネオン紫陽花1系譜**、**基本5色固定**（仕事=紫/家事育児=桃/学習開発=緑/からだ=アクア/趣味交流=金）
- **キャラは妹のスタンプ原案・白フチスプライト**

## 進め方

- 決定は1つずつ。決める → docsに反映 → コミット、を終えてから次の議題へ
- 迷う見た目・手触りは、HTMLの比較ページを `previews/` に作って現物で判断する
- docsは追記パッチでなく統合改訂で更新する

## 次のステップ

1. **はじく操作の試作** — タネが飛んで、着地して、育って咲くところまで。指で触って手触りを決める
2. 未決定の細部を詰める（`未決定事項.md` の1〜13）。とくに月と年の行き来、特別な花の見た目
3. 画面フロー設計（`画面フロー.md` の末尾）
4. SwiftUIプロトタイプ：月の画面（草＋同じ大きさの紫陽花）、起動1秒以内
5. GitHub連携（その日にコミットがあったか）
6. キャラ基本実装（ユジュのひとこと、トゥーリの仕草と成長の最初の段階）
7. 願いリストと年の画面
