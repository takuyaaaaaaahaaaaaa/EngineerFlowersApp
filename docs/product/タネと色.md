# タネと色 — 今日あったことはどう花になるか

> 1日のマスが何で決まるか、タネがどこから来てどう咲くか、色の割り当ての正本。
> 見え方は `ビジュアルディレクション.md`、使われ方は `画面フロー.md` を参照。
> 旧 `スコアリングモデル.md` の後継。量を点数にする仕組み（軽中重、行動→点テーブル、表示段階）は廃止した。

## 1. 大原則：量は測らない。残すのは種類だけ【確定】

1日のマスを決めるのは **「その日、どの種類のことがあったか」** だけ。

- 何時間やったか、何回やったか、何コミットかは見ない
- どの日の花も同じ大きさ。頑張った日ほど大きい、という表現はしない
- 色の割合も等分。仕事が8割の日でも、仕事の色が多くなることはない

### なぜ測らないか

量で花の大きさが決まると、小さい花の日が必ず生まれる。寝かしつけで力尽きた日に小さな花が表示されることは、落ち着くアプリ（柱1）と両立しない。比べる材料そのものを持たないことにした。

---

## 2. 1日の状態【確定】

| 状態 | 月の画面 | 年の画面 | 意味 |
|---|---|---|---|
| 草だけ | 草が生えている | 草色のマス | 記録のない日。空白ではない |
| 咲いた | 草の上に、同じ大きさの紫陽花。その日あった種類の色が等分に混ざる | マスがその色に色づく | 何かあった日 |
| 特別な花 | 普段とは違う一輪 | ひときわ明るく灯る | 願いが叶った日 |

- **空白の日は存在しない**。アプリを開かなくても草は生える
- **自動で花を咲かせない**。本人が何も言っておらず、連携からも何も来ていない日は草のまま（花が嘘にならないように。そこは草が引き受ける）

```swift
struct Day {
    var categories: Set<Category>   // 空なら草だけ
    var fulfilledWishes: [Wish.ID]  // 空でなければ特別な花
}
```

---

## 3. タネ：見つかる → 手元に届く → 飛ばす → 咲く【確定】

1. **見つかる**：連携（GitHub、HealthKit、X）が、今日あったことをタネとして拾ってくる。自分で足すこともできる
2. **手元に届く**：アプリを開くと、今日のタネが手元に集まっている。タネの色＝種類の色
3. **飛ばす**：タネをはじいて庭へ飛ばす。連携はタネを拾ってくる係で、蒔くのは自分
4. **咲く**：着地したタネが育って、その色の紫陽花になる

**蒔かれなかったタネはトゥーリが蒔く**：開かなかった日のタネは、日付が変わったらトゥーリが蒔いておく。次に開くと花は咲いている。連携で何かあった日が草だけになることはない。

---

## 4. タネの入り口【確定】

| 入り口 | 見るもの | 種類の決め方 |
|---|---|---|
| GitHub | その日にコミット等があったか | 学習・開発 |
| HealthKit | その日に運動・睡眠の記録があるか | からだ |
| X 投稿 | 本人の投稿 | FMで文章から種類を判定 |
| 音声・手動メモ | 自分で足した内容 | FMで判定、または自分で色を選ぶ |
| ユジュとの会話 | 空いた日に答えた内容 | 同上 |

- 数えられるものは「あったか、なかったか」だけを見る（件数や時間は使わない）
- Xはリプライ・引用を除外し、本人の発信のみ
- 同じ日に同じ種類が複数の入り口から来ても、花の見え方は変わらない（その色がある、というだけ）

### ユーザーができること

- 見つかったタネを捨てる
- 種類（色）を直す
- 自分でタネを足す

## 5. FoundationModel の担当【確定】

自分専用・iPhone最新機・Apple Intelligence有効を前提とし、汎用配布向けフォールバックは最小にする。

- FMの担当は **文章から種類を当てること** だけ。強度（軽中重）の判定は廃止した
- `SystemLanguageModel` が `.unavailable` のときは、種類を決めずに保留し、ユーザーが色を選ぶ
- 後で直せるよう、元テキストは端末内に残す

```swift
@Generable
struct SeedCandidate {
    @Guide(description: "短い行動名") let title: String
    @Guide(description: "カテゴリ") let category: Category
}
```

## 7. カテゴリと配色【確定】

種類は5つ。**交流は趣味に吸収**、**からだ（運動・休息・睡眠）を独立**させている。「動かす」も「休める」も身体を整えること、として同じ屋根に入れた。休んで充電した日は「からだ」の色で咲く。

配色の前提：背景が紺の夜の庭なので**紺に溶ける色（特に青）は使えない**。
色相をホイール上で約70°間隔に均等配置 → (a)同系色が隣り合わない／(b)加法混色で濁らない、の両方が成立。

### 基本5色

| カテゴリ | 色名 | HEX | メモ |
|---|---|---|---|
| 仕事 | バイオレット | `#A77BFF` | 落ち着いた集中の色 |
| 家事・育児 | ピンク | `#FF5C9E` | 温かさ・家庭。ユジュの花と揃う |
| 学習・開発 | ライムグリーン | `#6FE85C` | GitHubの草。イン/アウト両方ここ |
| からだ | アクア | `#25DDD0` | 運動・休息・睡眠。水・回復・コンディション |
| 趣味・交流 | ゴールド | `#FFC93C` | 遊び・宝物。登壇/コミュニティもここ |

### ライトUI用インク変種

基本5色は紺の庭で光る前提のネオン値。白背景のUI（設定・シェアカード等）ではゴールド・ライム・アクアが沈むため、別途インク版を持つ。
**ルール＝色相は固定したまま、白背景でコントラスト3.0:1（WCAG AA図形・アイコン基準）になる明るさまで濃くする**。

| カテゴリ | 庭のネオン（正本） | ライトUIインク | 白 / 紺 コントラスト |
|---|---|---|---|
| 仕事 | `#A77BFF` | `#A77BFF`（元々3.0で変更なし） | 3.0 / 5.2 |
| 家事・育児 | `#FF5C9E` | `#FF549A` | 3.0 / 5.3 |
| 学習・開発 | `#6FE85C` | `#25AC10` | 3.0 / 5.3 |
| からだ | `#25DDD0` | `#12A69C` | 3.0 / 5.2 |
| 趣味・交流 | `#FFC93C` | `#C18B00` | 3.0 / 5.2 |

- 庭画面は常にネオン正本（追従しない）。インクは**UI部分のライトモード時のみ**使う。
- 3.0:1はアイコン・凡例ドット・色付き太字向けの最低ライン。小さい本文に色を載せるなら4.5:1へ上げる余地あり。

### カスタム用ストック（追加色・4色が上限）

基本5色の色相の隙間（4ヶ所）の中間に置く。70°間隔がすでに埋まっているため5色目は必ずどれかの隣になる。

| 色名 | HEX |
|---|---|
| コーラル | `#FF6A4D` |
| ローズ／マゼンタ | `#E85CD0` |
| スカイブルー | `#4FA8FF` |
| ミント | `#4FE3A8` |

### 注意点（実装時）

- 仕事のバイオレットが紺地に最も近い → 沈むなら一段明るく（`#B891FF`）or 割り当て変更を検討
- 最も近いペアは 学習・開発(緑) ↔ からだ(アクア)（色相67°差）→ 両方ある日に隣り合わせない配置を効かせる
- 草の緑と、学習・開発／からだの色が近い。草は暗く光らせず、花だけを光らせて分ける（→ `ビジュアルディレクション.md`）
- カテゴリ間はグラデーションで連続させない。小花序ごとにソリッド色で置く
- カテゴリ内だけ `hueDrift` で淡さ/隣接色相への微小な揺れを許す
- 中心の芯は淡いクリーム1色で固定（`#F5EFD8`〜`#FBF3DD`）。色違いの花が並んでも同じ品種に見える
