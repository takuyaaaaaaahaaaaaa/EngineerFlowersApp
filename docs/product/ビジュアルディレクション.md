# ビジュアルディレクション — がんばっタネ / EngineerFlowers

> 見た目・世界観・アニメの正本。1日のマスが何で決まるか、色の割り当ては `タネと色.md` が正本（ここは見え方を扱う）。

## 世界観の核：「あなたの毎日が描き込まれていく絵本」

星型・廃墟型・絵本型を比較した結果、**絵本型を採用**。ただし「閉じた物語」ではなく**「器」**。

- 絵本は器。中には生きた庭が広がる（ポップアップ絵本のイメージ）
  - 閉じた挿絵だと鳥・風・飛んでくるタネなど「外から来る」演出が乗らない → 器にして回避
  - ページを開くと庭が立ち上がり、風が吹き、子どもが遊ぶ
- 子どもは「絵本の登場人物」ではなく**「庭にいる我が子」**
- 物語の核：**何もしなくても草が生え、あったことが花になって描き加えられていく絵本**

---

## 質感：紺ペンキの夜の庭 × 白い紙

- ベースは**白い絵本のページ**。そこに**紺のペンキを刷毛で雑に塗る**（ムラ・筆跡あり）
- ページの**外周・四隅に塗り残しの白が覗く**（雑さ＝手作り感）
- その紺の上に**草が生え、ネオンの花**が咲く
- 解いている課題：
  - 「ネオンは暗背景が要る／紙は明るい」の両立 → 紺塗り=暗い庭、白余白=紙、で一枚に共存
  - SVG/ベクターのパキッと感でヨシタケ感が出ない → 塗りムラ・筆跡・塗り残しが温かさを担う
- **質感の三層**：庭＝紺ペンキと暗い草／花＝ネオンの発光／子ども＝黒線＋白フチのスプライト
- 実装では絵の具テクスチャ画像を使うと本物感が出る
- システムのライト/ダーク：**庭画面は常に独自の暗いトーン**（追従させない）。UI部分（設定・メニュー）はシステム追従

## 画面：同じ草むらの2つの縮尺

| | 月の画面 | 年の画面 |
|---|---|---|
| 見えるもの | 30日のマス。草と花が1つずつ見える | 365日の草むら全景。本家の草と同じ形（週の列×7日） |
| 普段の日 | 同じ大きさの紫陽花に、あった種類の色が混ざる | マスそのものが色づく |
| 記録のない日 | 草だけ | 草色のマス |
| 願いが叶った日 | 普段と違う特別な一輪 | ひときわ明るく灯る |
| 属するもの | 今日あったこと、ユジュとの会話、タネを飛ばす操作 | 今年の願いリスト |

- 近くで見れば花の姿、引いて見れば色の粒。比較検討は `previews/daily-cell-compare.html`
- 願いは月の画面に常時は見せない（「まだ叶っていない」を毎日気にさせないため）
- 収集のための別の棚は作らない。**年の草むらそのものがコレクション**で、灯った点の数が今年叶った願いの数

### 月の画面のレイアウト
- **縦スマホ＝1か月30日を一画面**（6×5）。スクロール不要で「ひと月の庭」が完結
- フレームは**ページの重なり**（前月・来月が後ろに覗く厚み）で絵本感を出す

### 折りたたみ見開き
- **折りたたみ全開＝見開き**。物理的な開閉＝絵本を開く/閉じる、と一致する
- **見開き＝鑑賞・没入モード**：閉じている時＝カレンダー、開く＝マスが溶けて地続きの生きた庭になる。MVPは格子を保ったまま余白・アンビエント（空・光・キャラ）を足したリッチ鑑賞から始める
- 年の画面と見開きの関係（開いたら年の画面にするか等）は未決定 → `未決定事項.md`
- 綴じ目（折り目）はヒンジ位置に合わせる。左綴じ/右綴じは実機仕様で確定

## 草

- **どのマスにも必ず草が生えている**。空白のマスは存在しない
- 草・茎・葉は深い葉色 `#244C38` を基調に、**暗く、glowしない**
- ねらい：光るのは花（意味を持つ色）だけの特権にする。学習・開発（ライム）やからだ（アクア）の花と、草の緑を明るさで分ける
- 検証：対ライム 6.2:1 / 対アクア 5.7:1（花より十分暗い）／ 対紺 1.6:1（庭に沈んで馴染む）
- 草だけのマスが寂しく見えすぎないこと。草むらとして十分きれいであることが、このアプリの優しさの土台になる

## 花のデザイン

### 普段の花：同じ大きさのネオン紫陽花
- **1マス＝1輪**。四角いマスに、線が発光する手描きのネオン花。ヨシタケ風の温かさ × ネオンの光
- 標準花は**ネオン紫陽花**に固定。**大きさ・小花序の数はどの日も同じ**
- その日あった種類の色が、小花序に**等分**で配られる。1種類の日は一色、3種類の日は三色の毬
- 紫陽花は小さな花序の集合なので、複数の種類があった日が「いろんなことが同じ日に集まって咲いた毬」として自然に読める
- マスをタップすると、その日にあったことが見える

### 紫陽花として効かせる要素
- **小花序の重なり**：整った十字ではなく少し回転をずらす。ピンウィール感が最も効く
- **毬の中の色ゆらぎ**：カテゴリ間はソリッド。カテゴリ内だけ淡さ・微小な色相ズレを許す
- **ドーム状の塊**：中心を密に、縁の花序を少し小さく外向きにして、平面円ではなく半球に見せる
- **小花序の形＝4萼ピンウィール × 浅い切れ込み**：小マスではディテールを描き込みすぎない（形・色だけで読ませる）
- **標準形＝手まり咲き（mophead）**：額咲き/ゆるい房は季節・拡大時の例外表現に退避
- **中心の芯＝淡いクリーム1色で固定**
- 花の結晶化（宝石化）はしない。ガラス質ネオン（透明感・薄い面・発光する線）は可

### 特別な花：願いが叶った日
- 普段の紫陽花とは違う一輪。**豆粒サイズ（年の画面）でも特別と分かること**が条件
- 形・色・光り方は未決定 → `未決定事項.md`
- 旧案の「果物型の宝石」「実った夢の棚」は廃止した

### 読めることとサプライズの線引き
**意味を運ぶ情報は決定的で読める。サプライズは意味を運ばない装飾・演出にだけ載せる。**
色＝種類は絶対に裏切らない。驚きは咲くアニメの開いていく瞬間や、季節の装飾などが担う。

## キャラクター：ユジュ & トゥーリ

### 出自とデザイン方針
- **開発者の妹が描いた手描きスタンプ**を原案にする（ちょんまげ=黒一房、点目、ゆるい眉、よれた輪郭、脱力ポーズ）
- これを子供っぽく調整（頭身を下げ、ほっぺふっくら、手足を短く丸く、線を丸く）
- 最終的な清書は**妹本人に監修/作画**してもらうのが理想（クオリティ・権利・家族の温かさのどれにも合う）
- **紺背景でのキャラ表現＝白フチ（ステッカー形式）を採用**
  - 黒線・黒点目・墨ちょんまげをそのまま使える＝妹の絵柄を損なわない
  - 紺の庭の上を自由に動ける。実装上もスプライトとしてオーバーレイ＝動かしやすい
  - 白チョーク画（紺地に白線）は不採用（繊細な表情が背景に溶ける）
- 2人は飾りではなく、このアプリを開く理由そのもの。開発者の実際の子どもの仕草を観察して写す

### ユジュ（お姉ちゃん）＝話し相手
花が大好きで元気いっぱい。好きな人に花を贈りたくなる優しい性格。丸いおばけのようなポーズをよくとる。
時々「バブー」と謎の言葉を発する。

- **ユーザーに話しかけるのはユジュだけ**。UIの文言や通知としてではなく、ユジュのセリフとして尋ね、受け止める
- 空いた日があると「さいきん なにしてたの？」と聞く。子どもの「なにしてたの？」は詰問にならない
- 答えは何であれ肯定で返す。休んだだけなら「げんき いっぱいに じゅうでん してたんだね！」
- 罪悪感を生むセリフは言わない（旧案の、長期離席後「ずっと待ってたよ！」は見直し対象）

### トゥーリ（弟）＝仕草の担当、少しずつ育つ
葉っぱが大好きで「ハッパ」を「アッパ」と発音する。無邪気。

- 基本はしゃべらず、草むらで仕草をしているだけ。意味も機能もなく、ただそこにいる
- **使い始めてからの日数で勝手に育つ**：ハイハイ → 自然と立つ → 言葉を真似する → 活発に動き回る
  - 記録の量やアプリを開いた回数では育てない（「まだハイハイなのは自分のせい」という焦りを作らないため）
  - しばらく開けなかった後に開いたら立っていた、という再会が喜びになる
- **蒔き残したタネを蒔いておいてくれる**。次に開くと花が咲いていて、トゥーリが得意げにしている
- 育てた草花を倒すなど、庭に害のあるいたずらはしない

### 役割と演出
- 日常の小さな物語（2人の掛け合い）／花が咲いたら拍手／願いが叶った日のお祝い／飛んでいくタネを目で追う
- ユーモアの方向性＝**「そうはならんやろ」**：押し付けがましくない不思議。真面目に変なことをやっている感じ

## タネを飛ばす

- アプリ名「がんばっタネ」のとおり、**自分の手でタネを飛ばして蒔く**。気持ちよく蒔けることが最優先
- 操作＝**はじく**：タネを上に向かってさっと払う。片手の親指だけで、数個を続けて蒔ける
  - 引っぱって放す（溜める）方式、長押しは採らない
- タネの色＝種類の色。飛んで、今日のマスに着地し、育って咲く
- 飛ぶ速さ・軌道・着地から咲くまでの間・触覚フィードバックは試作で調整する → `未決定事項.md`

## 咲くアニメ：花火ブルーム

咲く瞬間を **茎が伸びる → 静かな破裂 → 小花序が集まる → ネオン紫陽花の毬として残る** の流れに。
ネオンと花火は「発光する線」という同じ言語。派手にしすぎず、日常に添う**静かな花火**を基本トーンに。

### 成長シーケンス
着地したタネから育つ物語と一体にする：
**茎が下から伸びる → 葉が左右に開く → さらに茎が伸びて頂点へ → 先端で破裂して花序が放射 → 手まり紫陽花として残る**。
- 伸びる茎の先端に光る点（＝花火の弾）が走り、頂点の破裂につながる。茎・葉は深い葉色 `#244C38`（非glow）
- 強度2段階：**静かな花火（普段の日）**／**本気花火（願いが叶った日）**＝放射広め・スパーク多数・二段破裂
  - 普段の日どうしで強度に差はつけない（量を測らないため）
- 検討用プロトタイプ：`previews/hydrangea-bloom.html`（実描画は `previews/hydrangea-prototype.html` 由来）

### 構成ルール
- 色＝種類（花序ごとに1色ソリッド）。配色は円周に順に配り、同系色を隣に置かない
- **重なり順**：外周/奥の花序を先に、中心/手前の花序を後に描く。中心ほど明るく、縁ほど少し小さく暗め
- **中心の芯**：咲くとき一度ふわっと光り、その後は静止して光り続ける（脈打つループは入れない）
- 火花（スパーク）の色は、飛ばしたタネの色

### 再生のタイミング
**自分でタネを飛ばした瞬間だけアニメさせる。それ以外は静止画。**

- 庭を開くたびには発火させない（30マス一斉発火しない）→ 特別感を保ち負担ゼロ
- 自分の操作への即時ごほうびになる
- トゥーリが蒔いておいたぶんは、開いたときにはもう咲いている

### 実装メモ
- 咲く瞬間だけ重い演出（SpriteKitは演出時のみ）。普段は静止で軽い
- **Reduce Motion 対応**：一瞬で咲く簡易版を用意
- 一覧の小マスは潰れるので、フル花火の見せ方（拡大するか等）は試作で判断
