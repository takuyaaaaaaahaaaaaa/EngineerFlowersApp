# ビジュアルディレクション — がんばっタネ / EngineerFlowers

> 見た目・世界観・アニメの正本。花序数や色の決定ロジックは `スコアリングモデル.md` が正本（ここは見え方を扱う）。

## 世界観の核：「あなたの毎日が描き込まれていく絵本」

星型・廃墟型・絵本型を比較した結果、**絵本型を採用**。ただし「閉じた物語」ではなく**「器」**。

- 絵本は器。中には生きた庭が広がる（ポップアップ絵本のイメージ）
  - 閉じた挿絵だと鳥・風・訪問生き物など「外から来る」演出が乗らない → 器にして回避
  - ページを開くと庭が立ち上がり、鳥が飛び、風が吹き、子どもが遊ぶ
- 子どもは「絵本の登場人物」ではなく**「庭にいる我が子」**
- 物語の核：**あなたの頑張りで毎日描き加えられていく絵本**

## 質感：紺ペンキの夜の庭 × 白い紙

- ベースは**白い絵本のページ**。そこに**紺のペンキを刷毛で雑に塗る**（ムラ・筆跡あり）
- ページの**外周・四隅に塗り残しの白が覗く**（雑さ＝手作り感）
- その紺の上に**ネオンの花**が咲く
- 解いている課題：
  - 「ネオンは暗背景が要る／紙は明るい」の両立 → 紺塗り=暗い庭、白余白=紙、で一枚に共存
  - SVG/ベクターのパキッと感でヨシタケ感が出ない → 塗りムラ・筆跡・塗り残しが温かさを担う
- **質感の三層**：庭＝紺ペンキ／花＝ネオンの発光／子ども＝黒線＋白フチのスプライト
- 実装では絵の具テクスチャ画像を使うと本物感が出る
- システムのライト/ダーク：**庭画面は常に独自の暗いトーン**（追従させない）。UI部分（図鑑・設定・メニュー）はシステム追従

## レイアウト：折りたたみ前提

- **縦スマホ（基本）＝1ヶ月30日を一画面**（6×5）。1マスは小さくてOK（小さな光が30個並ぶと星空のよう）。スクロール不要で「ひと月の庭」が完結
  - 14日案は半端に見えたため不採用、30日フルに
- **折りたたみ全開＝見開き**。本命のごほうび体験。**物理的な開閉＝絵本を開く/閉じる**と一致（絵本フレーム採用の決定的理由）
  - **見開き＝鑑賞・没入モード【確定】**：閉じている時＝カレンダー（情報）、開く＝**マスが溶けて地続きの生きた庭**になる（候補C）。「開いたら世界が広がる」驚き＝物理開閉のワクワクと「毎日が描き込まれる絵本」という世界観の核に一致。比較ツール(A)・単純拡大(B)はごほうびの位置づけと噛み合わないため不採用。
  - **段階導入で重さと両立**：方向性はフルモーフのCを本命（北極星）に据えつつ、MVPは「**格子を保ったまま余白・アンビエント（空・光・キャラ）を足したリッチ鑑賞**」から始め、格子→自由配置のモーフを段階的に育てる。
- 綴じ目（折り目）はヒンジ位置に合わせる。左綴じ/右綴じは実機仕様で確定
- フレームは**ページの重なり**（前月・来月が後ろに覗く厚み）で絵本感を出す

## 花のデザイン

### 表現の核：カレンダーのマスに咲くネオンの花
- 四角いマス（=1日）に、線が発光する手描きのネオン花。ヨシタケ風の温かさ × ネオンの光
- **1マス＝1輪**（一覧性を最優先）。各マス＝暗い土にネオンの花（背景は紺の庭）
- **咲いたら種は表示しない（花だけ）**。タップで根元の種が顔を出す＝その日の凡例
- 空きの日は土だけ（プレッシャーにならない暗さ）
- 花序数の多い日は一覧では簡略表示、タップで詳細

### ネオン紫陽花1系譜を「量で育てる」
- シンプル図形の組合せではなく、**綺麗なイラストの花**。標準花は**ネオン紫陽花**に固定し、違いは花序数・毬の密度/大きさ・色と光で出す
- 成長段階：**芽（双葉）→ 小さな紫陽花 → 普通の紫陽花 → 大きな手まり紫陽花**（量で花序数と毬の密度が増える）
  - 一覧で「今日は毬が大きい/密＝よく動いた日」が一目で分かる＝数値的達成感の視覚化
- 互いにぶつからない軸：**色＝種別／花序数・毬の密度・大きさ＝量**（中心の白熱は廃止、`スコアリングモデル.md` 参照）
- 実装：別アセットにせず、**小花序の数・配置密度・ドーム感をパラメータ化した1つの紫陽花**として生成
- コスモス/ダリア等は標準成長段階ではなく、季節テーマ・月間ハイライト・特別演出の候補として扱う

> 量・段階・色数の確定ルールは `スコアリングモデル.md` が正本。

### ミステリー vs 凡例性の線引き【確定】
「色で読める（凡例性）」と「植えるまで不明（ミステリー）」は逆向き。原則で両立させる：
**意味を運ぶ情報は完全に凡例的（決定的・読める）。ミステリーは"意味を運ばない装飾・演出レイヤー"にだけ載せる。** データ（色＝種別・花序数＝量）は絶対に裏切らない。

| | 決定的・読める（凡例死守） | ミステリー・サプライズOK |
|---|---|---|
| 日々の紫陽花 | カテゴリ色・花序数=量・成長段階 | （なし＝完全に読める） |
| 果実 | 宝石色＝夢カテゴリ | 果物の**形**（5〜8種のどれが実るか） |
| 演出レイヤー | — | レア花の出現・訪問生き物・季節の特別花 |

- 強さは**中程度**：果実の形＋レア花・訪問生き物・季節花までサプライズ。情報レイヤーには一切ミステリーを載せない。
- reveal の喜びは「咲くアニメの開いていく瞬間」が担う＝情報を曖昧にしなくてもワクワクは出せる。

### 紫陽花として効かせる要素
- **小花序の重なり**：整った十字ではなく少し回転をずらす。ピンウィール感が最も効く
- **毬の中の色ゆらぎ**：カテゴリ間はソリッドで凡例性を守る。カテゴリ内だけ淡さ・微小な色相ズレを許す
- **ドーム状の塊**：中心を密に、縁の花序を少し小さく外向きにして、平面円ではなく半球に見せる
- **小花序の形**：4萼ピンウィールと「浅い切れ込み5枚」パターンをプロトタイプで比較。小マスではディテールを描き込みすぎない

### 茎・葉の色【確定】
- **茎・葉は深い葉色 `#244C38`（緑寄り・暗い・glowしない）で固定**。
- ねらい：花序の glow するネオン（特にライム＝学習開発、アクア＝からだ）と**明るさで明確に差をつけ、別レイヤー（＝構造）として読ませる**。これで「1輪に緑が2つ」の二重表現が解消する。
- 検証：対ライム 6.2:1 / 対アクア 5.7:1（花序より十分暗い）／ 対紺 1.6:1（庭に沈んで馴染む）。色相は緑のままでも明度差で競合しない。
- 茎・葉は **glow をかけない**（発光は花序＝意味を持つ色だけの特権にして、構造と信号を分ける）。実際の紫陽花の茎も暗い緑なので自然。

### 継続の表し方（結晶化は不採用）
- **花の結晶化（宝石化）は不採用**：ネオンの透ける発光・花序の繊細さが硬い面に上書きされて死ぬ。花序数=量の情報とも衝突
- **ガラス質ネオンは可**：硬い切子面ではなく、透明感・薄い面・発光する線を保つ表現なら紫陽花の立体感に使える
- **花は最後まで綺麗なネオンの花のまま**。継続は果実（達成）／カウンター（連続日数・累計）／背景・空の変化で表す

## 果実（一回の大きな達成の結実）＝果物型の宝石

- 花＝その日の「瞬間」、果実＝「一回の大きな達成の結実」。時間軸の違うものを同じマスに置ける
- デザイン＝**実在の果物の形 × 中身を結晶化した宝石**
  - 好きな果物（バナナ・トマト・スイカ・ブルーベリー等）のシルエットで一目で分かる
  - 中身はファセット（切子面）を持つ宝石で内側から光る（スイカ=紅／ブルーベリー=紫水晶／トマト=ルビー／バナナ=黄水晶）
  - 「割ると中が宝石」＝ヨシタケ風の「そうはならんやろ」感
  - 花（発光する線）と果実（面で輝く塊）で質感がはっきり分かれる
  - 中の宝石色で夢のカテゴリを示せる。形は5〜8種の果物セット（どれが実るかはミステリー要素にできる）
- 意味づけ：夢のタネの達成／リリースタネ（＝単発の大きな達成）。大きさで規模を出す
- 果実の上に**枯れた花の名残（がく）**を添えると「花が実になった」因果が伝わる
- 描画の二段構え：一覧（瓶/カゴ）では「光る塊+色」に簡略化、タップ拡大でファセットを見せる

### 花と果実が同じマスに来る日【確定】
夢のタネ達成日・リリース日などは、その日の日常の頑張り（紫陽花）と大きな達成（果実）が1マスに同居する。

- **果実が主役**：夢達成は特別な日なので、果実を大きめ・中心に置き、宝石のきらめきで「この日が特別」と伝える。
- **日常の紫陽花も足元に同居**：その日も頑張った事実は消さず、紫陽花を小さく足元に咲かせる。果実は紫陽花の中心/足元に実り、**がく名残**で「花が実になった」因果を見せる（＝合体した1オブジェクトとして扱い「1マス＝1輪」の一覧性を壊さない）。
- **30マス一覧**（小マスで潰れる）では、果実のきらめきを"特別な日マーカー"として優先表示 → **タップで紫陽花＋ファセット果実をフル表示**。
- **棚との二重表示はOK**：同じ果実が「その日のマス（＝日々の記録）」と「実った夢の棚（＝夢のアーカイブ）」の両方に出る。文脈・時間軸が違うため重複ではなく役割分担。

### 「実った夢の棚」（コレクション）
- 花の図鑑マトリクスは廃止（1系譜固定で色違いを集めてもコンプ感が薄いため）
- 夢のタネ→果実の出口として、叶えた夢が果実になって**ガラス瓶/カゴに堆積**
- 第一候補はガラス瓶（宝石果実がガラス越しに透けて暗い庭でも映える）。上に瓶、下に夢のタネ一覧
- 積もり方：MVPは達成数に応じた**事前定義のパターン配置**。拡張で達成の瞬間だけ物理演算→落ち着いた配置を保存→以降静止
- 拡張：ユジュ＆トゥーリが透明なカゴ/リュックを背負い、達成のたびに宝石果実が入る

## 咲くアニメ：花火ブルーム

咲く瞬間を **打ち上げ → 静かな破裂 → 小花序が集まる → ネオン紫陽花の毬として残る** の流れに。
ネオンと花火は「発光する線」という同じ言語。派手にしすぎず、地味な頑張りに添う**静かな花火**を基本トーンに。

### 構成ルール（`スコアリングモデル.md` の具体化）
- 色＝種別（花序ごとに1色ソリッド）／量＝花序数・毬の密度/大きさ
- **重なり順**：外周/奥の花序を先に、中心/手前の花序を後に描く。中心ほど明るく、縁ほど少し小さく暗め
- **中心の芯**：咲くとき一度ふわっと光り、その後は静止して光り続ける（脈打つループは入れない）。芯は淡いクリーム1色固定
- 配色はラウンドロビンで円周に配り、同系色を隣に置かない（→ `スコアリングモデル.md`）
- 火花（スパーク）の色は、その日のカテゴリの色を散らす

### 再生のタイミング ★主要決定
**「タネを植えた瞬間だけアニメさせる。それ以外は静止画」** に統一。

- 庭を開くたびには発火させない（30マス一斉発火しない）→ 特別感を保ち負担ゼロ
- 自分のアクションへの即時ごほうびになる
- トリガーは実質3つ：①手動で植えた直後（1回）／②自動で植わったぶん（X/GitHub/HealthKit）は初回表示 or 夜の振り返りでまとめて1回／③（任意）詳細画面でのリプレイ

### 実装メモ
- 咲く瞬間だけ重い演出（SpriteKitは演出時のみ）。普段は静止で軽い
- **Reduce Motion 対応**：一瞬で咲く簡易版を用意
- 一覧の小マスは潰れるので、フル花火は詳細表示で見せる二段構え

## 季節システム

- 実際の季節に合わせた装飾や特別花（春=桜/チューリップ系・夏=ひまわり/朝顔系・秋=コスモス/紅葉系・冬=雪結晶/椿系）
- 絵本型なので、季節でページの紙質・装飾・空の色を変えるだけで雰囲気を切り替えられる
- 庭の空を時間帯で変化（朝=藍が薄まる／夜=深い藍）。どの時間帯もネオンが光れる暗さはキープ → 夜の振り返りモードと接続
- 標準花は紫陽花1系譜固定。季節花は標準成長を置き換えず、季節テーマ・記念日・月間ハイライトなどの例外表現として扱う

## 訪問する生き物
- 個性的な動物が名言やコメントを残す。いいね・スター数などの反応があると訪れる（器なので外から来る演出が成立）
